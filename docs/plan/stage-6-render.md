# Этап 6. Сборка дайджеста (ru / en / uz)

**Цель.** Команда `uzdigest digest` сама определяет окно, прогоняет этапы 3–5 и записывает файлы в `outputs/ГГГГ-ММ-ДД/`:
- три `.md` в формате из PLAN.md, раздел 7;
- `digest.json` для генератора постов.

**Оценка:** 1,5 дня. **Зависит от:** этапа 5.

---

## Окно дайджеста
- **Начало:** `window_to` последнего успешного запуска `digest` (`runs.kind='digest'`, `status='ok'`). Если такого нет — сейчас − 24 ч.
- **Границы:** не меньше 24 ч, не больше 96 ч (`digest.max_window_hours`). В понедельник получается около 72 ч.
- **Конец:** момент запуска.
- **Выбор материалов:** в окно попадают материалы, у которых `published_at` в окне.
- **Повторный запуск в тот же день** (`--force`) пересобирает дайджест с тем же окном, кэш Claude используется.

## Структура файлов

```
outputs/2026-11-02/
├── digest.ru.md
├── digest.en.md
├── digest.uz.md
└── digest.json
```

### Markdown
- **Шапка (front matter):** `date`, `lang`, `window`, `items`, `sources_ok`, `generator` (версия, модель, версия промптов).
- **Заголовок и курсы:** заголовок дня, строка курсов ЦБ (USD, EUR, RUB с изменением), если они есть в `fx_rates`.
- **Разделы по категориям** в фиксированном порядке: Законодательство → Налоги → Бухучёт и отчётность → Финансы и банки → Бизнес и инвестиции → Макроэкономика. Пустые разделы не выводятся.
- **Статья:**
  - `<!-- id: 2026-11-02-001 | doc_key: … -->`;
  - `### заголовок`;
  - «Краткое содержание»;
  - «Подробное содержание»;
  - строка «Документ» — только у правовых: вид, номер, дата, статус сверки, ссылка lex.uz на языке файла, дата вступления в силу;
  - «Источник» — ссылка и время публикации по Ташкенту;
  - «Также писали» — ссылки остальных материалов кластера;
  - метка `⚠️ проверить`, если есть флаги QA.
- **Блок «Обновления»:** акты, которые вышли раньше как «ожидает публикации» и теперь появились на lex.uz.
- **Подвал:** какие источники не ответили, сколько статей «без ИИ-обработки» или «перевод не готов».
- **Подписи** всех полей и разделов берутся из `config/i18n.yaml`. Таблица подписей — в PLAN.md, раздел 7.

## Задачи
1. **`src/uzdigest/pipeline.py`:** функция `build_digest(conn, settings, now)`. По порядку:
   1. окно;
   2. префильтр и кластеры (этап 3);
   3. сверка (этап 4);
   4. проходы Claude (этап 5);
   5. модель дайджеста;
   6. запись в `digests` и `digest_entries`;
   7. рендер.
2. **`src/uzdigest/render/model.py`** — модель дайджеста (она же схема JSON).
3. **`src/uzdigest/render/markdown.py` и `render/templates/digest.md.j2`** — один шаблон на три языка.
4. **`config/i18n.yaml`** — подписи, названия разделов и месяцев на ru, en, uz.
5. **Атомарная запись.** Сначала во временную папку, затем переименование. Читатели общей папки никогда не видят половину файла.
6. **CLI:**
   - `uzdigest digest [--force] [--date ГГГГ-ММ-ДД]`;
   - `uzdigest rerender ГГГГ-ММ-ДД` — только рендер из БД, без Claude и без сети;
   - `uzdigest run` = `collect` + `digest`, точка входа для планировщика.
7. **`pyproject.toml`:** добавить `Jinja2`.

## Тесты
- **Окно:** нет прошлых запусков; обычный день; понедельник; пропуск длиннее 96 ч (обрезка и предупреждение).
- **Снимок (snapshot):** фиксированная модель дайджеста → ожидаемые `digest.ru.md` и `digest.json`, сравнение с эталонными файлами в `tests/fixtures/`.
- **Структура:** у каждой статьи во всех трёх файлах есть четыре обязательных поля в правильном порядке, `id` совпадают между языками.
- **Ссылки lex.uz по языкам** соответствуют этапу 4.
- **Атомарная запись:** при ошибке рендера старая папка дня не испорчена.

## Готово, когда
- `uzdigest run` на живых данных создаёт папку дня с четырьмя файлами.
- Файлы соответствуют формату из PLAN.md, раздел 7.
- `rerender` воспроизводит те же файлы без сетевых запросов.

### Решения, принятые по ходу работы
- **Атомарная запись — по файлам.** Все четыре файла сначала целиком собираются в памяти, затем каждый пишется во временный `.digest.*.tmp` в папке дня и заменяет прежний одним `os.replace`. Подмена папки целиком на Windows не атомарна, а старая папка при этом никогда не удаляется. Ошибка рендера прежние файлы не трогает (проверено тестом).
- **Пересборка (`--force`)** берёт начало окна утренней сборки, а конец — момент запуска, как в `get_or_build_digest` этапа 8: новости, вышедшие после утра, добавляются. Повторы ищутся только в дайджестах прошлых дней, поэтому утренние сюжеты своего дня повторами не считаются.
- **`--date` не понадобился.** Прошлый день пересобирается из БД командой `rerender`; заново с новыми данными собирается только сегодняшний (`--force`).
- **Модель дайджеста хранится в БД** (`digests.model_json`). По ней `rerender` пишет файлы без сети и Claude, а «Обновления» находят акты, которые в прошлых дайджестах были «ожидает публикации», а теперь подтверждены. Каждое обновление выходит один раз.
- **«Не ответили»** — включённый источник с ошибкой последнего опроса или без успешного опроса 6 ч к концу окна (`pipeline.STALE_AFTER_H`): так видно и упавший источник, и пропущенный сбор.
- **Статус запуска.** `partial` и код выхода 1, если есть статьи без ИИ-обработки или без перевода, ошибки lex.uz или Claude остановлен. `partial`, как и `ok`, задаёт начало следующего окна.
- **Поля статьи — отдельными абзацами.** В примере PLAN.md, раздел 7, «Документ», «Источник» и «Также писали» идут подряд и в просмотрщиках Markdown сливаются в одну строку. «Также писали: —» выводится всегда: четыре обязательных поля есть у каждой статьи.
- **Ссылки на источник без `utm_*`** и других трекинговых параметров, остальной адрес как в источнике. Подпись ссылки — домен (`norma.uz`), у ведомств с gov.uz — `gov.uz/soliq`.
- **Без перевода** в en/uz выводится русский текст с пометкой «Translation not ready / Tarjima tayyor emas». Замечания проверки фактов подробно — только в русском файле, в en/uz метка со ссылкой на русскую версию.
- **`outputs/`** добавлена в `.gitignore`, как и `data/`.

### Найдено для пилота
- **Перевод с ошибкой в номере остаётся в файле** с меткой «⚠️ Check». Можно автоматически переводить такие статьи заново (этап 5) — решить на пилоте.
