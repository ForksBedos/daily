# Этап 2. Все источники, полный текст, догрузка, справочник актов, курсы

**Цель.** Собираются все источники из реестра. У каждого материала есть полный текст. Понедельничное окно (пт 09:30 → пн 09:30) не теряет материалы. Справочник `legal_acts` пополняется из lex.uz, курсы ЦБ сохраняются.

**Оценка:** 3 дня. **Зависит от:** этапа 1.

## Что выяснено (02.11.2026)

### gov.uz: единый JSON API для всех ведомств
- **Список новостей.** `GET https://api-portal.gov.uz/authorities/news/category?code_name=news&page=N`. Обязательные заголовки `code: <ведомство>` и `language: ru|uz`. 12 записей на страницу. Поля: `id`, `date` (`"2026-11-01 16:30:00"`, местное время Ташкента), `title`, `anons` (обычно пустой), `category_title`.
- **Полный текст.** `GET …/authorities/news/view?id=ID`, поле `body` в HTML.
- **Ведомства** (`total_page` — сколько страниц в архиве):

| Код | Ведомство | Язык | Активность | Решение |
|---|---|---|---|---|
| `soliq` | Налоговый комитет | ru | 97 стр., свежие | включить |
| `imv` | Минэкономфин | **только uz** (кириллица) | 122 стр., свежие | включить, `language: uz` (вопрос 2) |
| `miit` | Мининвестпромторг | ru | 65 стр., 28.10 | предложить (вопрос 3) |
| `adliya` | Минюст | ru | 38 стр., 30.10 | предложить (вопрос 3) |
| `icppa` | Агентство госзакупок | ru/uz | 9 стр. | позже |
| `raqobat` | Комитет по конкуренции | ru | последняя запись 05.2025 | нет |
| `investmiit`, `insolvency`, `udz` | — | — | редко или не по теме | нет |

- Таможня и статистика на gov.uz не представлены, у них свои сайты. Это этап 11.

### HTML-источники: хватает одного общего адаптера
`trafilatura` (уже стоит в `.venv`) правильно вытаскивает заголовок, дату (с точностью до дня) и текст на всех проверенных сайтах: cbu.uz, president.uz, buxgalter.uz, norma.uz, kun.uz, spot.uz, uzdaily.uz. Поэтому HTML-адаптер устроен так: со страницы-списка берутся ссылки по шаблону, затем каждая новая статья прогоняется через `trafilatura`. **beautifulsoup не нужен.**

| Источник | Страница-список | Шаблон ссылки | Дата в списке |
|---|---|---|---|
| president.uz | `/ru/lists/news` | `/ru/lists/view/\d+` | `span.date_text` = `30-10-2026` |
| buxgalter.uz | `/newssite/` | `/ru/publish/doc/text\d+_[^"]+` | `div.date_text` = `30.10.26`, анонс в `div.text_no_name` |
| podrobno.uz | `/cat/economic/`, `/cat/uzbekistan/`, страницы `?PAGEN_1=N` | `/cat/[a-z_-]+/[^"/]+/` | нет, берётся со страницы статьи |

Шероховатости `trafilatura`, которые нужно чистить:
- у buxgalter первой строкой идёт рекламный баннер («Закрываем 9 месяцев без ошибок:»);
- у president.uz заголовок повторяется в тексте с пробелами;
- у cbu в начале текста строка «Дата обновления: …».

Для этого нужен короткий список «мусорных» строк на источник в `sources.yaml` (`text_drop_lines`).

Сбор идёт по будням с 08:00 до 20:00. Самый большой пробел — с пятницы 20:00 до понедельника 08:00, то есть 60 часов.

| uza | 45 ч | **да** | месячный `https://uza.uz/sitemap/posts-ru-{Y}-{MM}.xml` с `lastmod` |
| podrobno | 48 ч, и в RSS нет анонсов | **да** | страницы рубрик `?PAGEN_1=N`. Sitemap не обновлялся с 2023 года |
| uzdaily | **3 ч** | **да** | `https://www.uzdaily.uz/sitemap-ru-articles-1.xml`: 5000 ссылок, ~850 КБ, `lastmod` с точностью до дня |

## Задачи

### 2.1 Миграция `002_stage2.sql`
- `items.text_status TEXT` со значениями `feed | fetched | failed | skipped` и `items.text_error TEXT`.
- `items.published_precision TEXT` со значениями `time | day`: у HTML-источников известна только дата.
- Таблица `fx_rates(date TEXT, ccy TEXT, rate REAL, diff REAL, PRIMARY KEY(date, ccy))`.
- `legal_acts.source TEXT` со значениями `lex_rss | lex_search | lex_page`.

### 2.2 Адаптер gov.uz — `src/uzdigest/sources/govuz_api.py`
- Параметры источника: `authority`, `language`, `max_pages` (по умолчанию 3).
- Листаем страницы, пока дата записи не станет старше `since`. Для новых `id` запрашиваем `view` и берём `body`.
- Ссылка материала: `https://gov.uz/{lang}/{authority}/news/view/{id}`.
- Время из API считаем ташкентским и переводим в UTC.
- В `sources.yaml` включить `soliq` (ru) и `imv` (uz); `miit` и `adliya` — после ответа на вопрос 3.

### 2.3 Справочник актов — `src/uzdigest/sources/lex_rss.py` и `src/uzdigest/legal/doc_key.py`
- Разбор описания по двум шаблонам. Вид акта приводится к коду:

| Вид акта | Код |
|---|---|
| Закон / Конституционный закон | `ZRU` |
| Указ Президента | `UP` |
| Постановление Президента | `PP` |
| Распоряжение Президента | `RP` |
| Постановление Кабинета Министров | `PKM` |
| Постановления Сената и Кенгаша Сената | `SENATE` |
| Акты ведомств с регистрацией в Минюсте | `MJ` |

- `doc_key` = `{код}-{номер}-{год принятия}`. Для ведомственных актов: `MJ-{рег. номер}` (номер регистрации в Минюсте уникален и без года).
- Запись в `legal_acts` через upsert по `doc_key`: `lex_id` из ссылки, даты принятия и вступления в силу, издатель, название.
- Стадия `collect` для вида `lex_rss` пишет только в `legal_acts`, в `items` ничего не попадает.

### 2.4 Полный текст — `src/uzdigest/extract/fulltext.py` и стадия `enrich`
- Функция `fetch_article(http, url) -> Article(title, date, text)` на основе `trafilatura.bare_extraction(html, url=…, with_metadata=True)`. HTML скачивается через наш `HttpClient`, чтобы соблюдать robots.txt и паузы.
- Стадия `enrich` запускается после `collect`:
  - обрабатывает материалы без `body` (`text_status IS NULL`) за последние 96 ч;
  - выкачивает их параллельно по доменам;
  - чистит текст по `text_drop_lines`;
  - ставит `text_status`.
- Полный текст берём **для всех** материалов без тела, а не только для релевантных. Это около 150 страниц в день, примерно минута с паузами по доменам. Зато дедуп и поиск номеров актов работают по полному тексту, а не по анонсу.
- Лимит `enrich.max_pages_per_run` (по умолчанию 300). Неудачи не повторяются бесконечно: не больше 3 попыток с интервалом в один запуск.

### 2.5 Общий HTML-адаптер — `src/uzdigest/sources/html_list.py`
- Параметры:
  - `list_urls` — одна или несколько страниц-списков;
  - `link_pattern` — регулярное выражение для ссылок на статьи;
  - `date_pattern` и `date_format` — необязательны;
  - `pages` — шаблон пагинации, например `?PAGEN_1={n}`, и `max_pages`.
- Возвращает `RawItem(url, title=None, …)`. Заголовок и текст заполняет `enrich`.
- Нужна правка модели: `RawItem.title` может быть пустым, если вид источника `html_list`. Тогда заголовок берётся из `trafilatura`, а материал без заголовка после `enrich` помечается как `failed` и в дайджест не идёт.
- Источники: president, buxgalter, podrobno (рубрики economic и uzbekistan; RSS у podrobno оставить для оперативности).
- Даты с точностью до дня: `published_at` = время первого обнаружения, но не позже конца указанного дня (ташкентского). Материалы, чья дата раньше начала окна, отбрасываются.

### 2.6 Догрузка — `src/uzdigest/sources/backfill.py`
- Параметр источника `backfill` с одной из стратегий:
  - `sitemap_daily` — kun, шаблон с `{d}`, `{Y}`, `{m}`;
  - `sitemap_monthly` — uza, шаблон с `{Y}`, `{MM}`;
  - `sitemap` — uzdaily, фиксированный адрес с фильтром по `lastmod`;
  - `feed_paged` — nuz, `?paged={n}`;
  - `list_paged` — podrobno, использует `html_list`.
- Фильтры: `url_filter` (например, `/ru/news/`) и `since`.
- Новые адреса записываются в `items` без текста, дальше их заполняет `enrich`.
- Запускается по правилу из раздела «Глубина лент». Не больше `backfill.max_urls` (150) адресов на источник за запуск.

### 2.7 Курсы ЦБ — `src/uzdigest/sources/cbu_rates.py`
- Раз за запуск `collect`: upsert в `fx_rates` всех валют за дату курса.
- Для дайджеста нужны USD, EUR, RUB (список в `settings.yaml`).

### 2.8 Конфиг и CLI
- `sources.yaml`: включить president, buxgalter, soliq, imv, lex. Добавить `backfill` для kun, uza, podrobno, uzdaily и nuz, а также `text_drop_lines`.
- `settings.yaml`: секции `enrich`, `backfill`, `rates`.
- `collect` выполняет по порядку: опрос → догрузку → `enrich` → курсы. Флаги `--no-enrich` и `--no-backfill` нужны для отладки.

## Итоги реализации (02.11.2026)

Код: [govuz_api.py](../../src/uzdigest/sources/govuz_api.py), [lex_rss.py](../../src/uzdigest/sources/lex_rss.py), [html_list.py](../../src/uzdigest/sources/html_list.py), [backfill.py](../../src/uzdigest/sources/backfill.py), [cbu_rates.py](../../src/uzdigest/sources/cbu_rates.py), [fulltext.py](../../src/uzdigest/extract/fulltext.py), [enrich.py](../../src/uzdigest/enrich.py), [doc_key.py](../../src/uzdigest/legal/doc_key.py), миграция [002_stage2.sql](../../src/uzdigest/db/schema/002_stage2.sql).

Решения, принятые по ходу работы:
- **Материалы без заголовка.** Ссылки из sitemap до `enrich` лежат в `items` с `title = ''`: колонка `NOT NULL`, а менять это ограничение в SQLite — значит пересобирать таблицу. Если `enrich` не нашёл заголовок, у материала `text_status = failed`.
- **gov.uz** отдаёт текст только через API, сайт — одностраничное приложение. У `soliq` и `imv` стоит `fulltext: false`: если в API тела нет, `enrich` ставит `skipped` и страницу не скачивает. Если `view` одного материала не ответил, материал не записывается и скачается в следующем запуске (предупреждение в логе).
- **Чистка текста.** Кроме `text_drop_lines` нужен `text_stop_lines`: у cbu после статьи идёт подвал сайта («Новое приложение…»), его проще отрезать целиком. Строка, совпадающая с заголовком, удаляется всегда.
- **lastmod в sitemap.** У uza `lastmod` совпадает с временем публикации из RSS (проверено на 4 материалах), у kun это время правки (на 2 дня позже). Отсюда флаг `lastmod_is_published` в `backfill`. У kun день публикации берётся из имени дневного файла. Дневной или месячный файл, которого ещё нет (404), считается пустым.
- **Адрес дневного sitemap kun** работает и с нулями, и без: `day_1` = `day_01`. В конфиге — без нулей.
- **Ключи редких видов актов.** Акты Сената хранят серию в номере: `SENATE-PK-411-V-2026`, `SENATE-PS-377-V-2026`. В ленте есть решение коллегии Верховного суда: вид `COURT`, ключ `COURT-5-1-267/13-2026`.
- **robots_exempt** относится только к самой ленте. Страницы статей, списки и sitemap всегда проверяются по robots.txt (у norma статьи вне `/ru/` разрешены, пауза 10 с соблюдается).
- **Курсы на дату**: `https://cbu.uz/ru/arkhiv-kursov-valyut/json/all/ГГГГ-ММ-ДД/` — проверено, формат тот же.
- **`collect --since ГГГГ-ММ-ДДTЧЧ:ММ`** (ташкентское время): считать пробелом всё время с этого момента, а не с последнего опроса. Нужен для проверки понедельника и после простоя ноутбука. Не глубже `collect.lookback_h`.
- **Извлечение реквизитов из текста** (задача 3.3 этапа 3) сделано сразу, в `doc_key.find_refs`: оно нужно и этапу 3, и этапу 4. 38 тестов на реальных фразах из собранных материалов и на ложных срабатываниях («скважина №604», «автобус №138», «№ 1 в рейтинге»).
- **Лимит догрузки** `backfill.max_urls` поднят со 150 до 300. На проверке понедельника у uzdaily за 72 ч оказалось 176 адресов, и лимит 150 сработал. Обрезанные адреса следующий опрос уже не догрузит: он считает пробел с момента этого опроса.
