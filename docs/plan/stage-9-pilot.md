# Этап 9. Пилот (тестирование на реальной работе)

**Цель.** За 1–2 недели реальной работы довести до уровня, который команда принимает:
- **дайджест** — без пропусков важного, без дублей, без ошибок в фактах и в переводе;
- **посты** — СММ публикует их как есть или с мелкими правками.

Пилот проходит **без бота**: бот подключается к уже принятой системе на этапе 10.

**Длительность:** 1–2 недели (5–10 рабочих дней). **Зависит от:** этапа 8.

---

## Роли

| Кто | Что делает на пилоте | Нужен ли терминал |
|---|---|---|
| **Оператор** (технический участник команды; может совпадать с админом) | Следит, что дайджест вышел (`uzdigest status`). Делает посты по заказу СММ (`uzdigest post …`). Записывает замечания (`uzdigest feedback add`). Вносит правки или поручает их Claude Code | да |
| **Админ** | Читает дайджест в `outputs/ДАТА/`, сообщает оператору о пропусках, дублях, ошибках | нет |
| **СММ** | Читает дайджест, выбирает темы и площадки, присылает оператору заказ: «статья 005, LinkedIn, en». Получает текст и оценивает его | нет |

Носитель узбекского проверяет `digest.uz.md` и узбекские посты.

## Как проходит
1. **Каждое утро** админ и СММ открывают дайджест из `outputs/ДАТА/`. Файл `.md` открывается в Блокноте или в любом редакторе как обычный текст. Номера статей (001, 002…) видны в файле.
2. **Посты.** СММ присылает оператору заказы (тема + площадка + язык). Оператор делает пост командой и пересылает текст. СММ ставит оценку: «как есть» / «мелкие правки» / «переделывать», и, если нужно, коротко пишет, что не так.
3. **Замечания** к дайджесту и постам оператор заносит в таблицу `feedback` (этап 8) одной командой на замечание. Типы:

   | Тип | Пример |
   |---|---|
   | `missed` | было в СМИ, нет в дайджесте; ссылка и почему важно |
   | `duplicate` | статьи 003 и 007 — один сюжет |
   | `irrelevant` | статья 012 не по теме |
   | `fact` | в статье 005 неверная сумма |
   | `translation` | статья 002, uz — неточный термин |
   | `post` | пост к 005 для LinkedIn: слишком сухо, нет крючка в начале |
   | `other` | всё остальное |

   Отдельные `.md`-файлы с замечаниями не ведём. Таблица `feedback` и таблица `posts` с оценками — единое место, куда после пилота будет писать и бот.
4. **Разбор раз в 2–3 дня.** Оператор выгружает замечания (`uzdigest feedback export`) и по каждому делает правку конфига или кода:

   | Замечание | Что правим |
   |---|---|
   | Пропуски | источники, рубрики, префильтр (`keywords.yaml`), порог важности |
   | Дубли | пороги `dedup`, новые случаи — в эталонную выборку |
   | Лишнее | стоп-рубрики, промпт отбора |
   | Факты | промпт `summarize`, проверка `qa.py` |
   | Перевод | `glossary.yaml`, промпт `translate` |
   | Посты | профиль площадки в `posts.yaml`, образцы СММ, промпт `post` |

   При правке промпта повышаем его версию. Кэш старой версии не используется.
5. **Наблюдение за эксплуатацией.**
   - Отработали ли все утра, включая понедельники.
   - Расход Claude на дайджест и на посты (`uzdigest status`).
   - Были ли упоминания лимитов.
   - Понятны ли тексты `uzdigest status`. Это будущие ответы бота, поэтому формулировки правим уже на пилоте.

## Требования к боту — собираем на пилоте
К концу пилота команда отвечает на вопросы, без которых этап 10 не начать:
1. **Telegram-аккаунты админа и СММ.** Бот узнает их ID при первом сообщении. Нужен ли доступ кому-то ещё и с какой ролью?
2. **Утренняя сборка в 09:30:** оставить, чтобы кнопка «Собрать новости» отдавала дайджест сразу? Без неё каждый раз ждать сбор около 10 минут.
3. **Площадки и языки по умолчанию** — окончательный список после пилота.
4. **Чего не хватало в процессе** без терминала: например, «дайджест за вчера», «пост сразу по двум темам», «картинка к посту для Instagram».
5. **Токен бота.** Кто из команды создаёт бота в @BotFather (5 минут, инструкция будет на этапе 10).

## Метрики приёмки (за последние 5 рабочих дней пилота)

| Метрика | Цель |
|---|---|
| Ошибки в фактах (дайджест и посты) | 0 |
| Дубли в одном дайджесте | ≤ 1 за неделю |
| Повторы из прошлых дней | 0 |
| Пропуски важного (по оценке команды) | ≤ 1 в день |
| Замечания к переводу uz/en | без замечаний по смыслу, только стилистика |
| Посты «как есть» или «мелкие правки» | ≥ 80 % |
| Посты в лимитах площадок | 100 % |
| Дайджест готов к 10:00 | 5 из 5 дней |
| Дни «без ИИ-обработки» | 0 |
